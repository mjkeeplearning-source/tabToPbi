# Visual Mapping Agent — Design Spec

**Date:** 2026-05-13  
**Status:** Approved  
**Goal:** Eliminate manual maintenance of `visual_conversion.md` and close runtime visual property gaps by building a hybrid registry + LLM fallback system.

---

## Problem

Visual property mapping (Tableau → PBI) is currently:

1. **Manually maintained** — `visual_conversion.md` was started mid-project and is incomplete. Validated mappings discovered during bug fixes (e.g. CrossTab `valuesOnRow`) are sometimes not recorded.
2. **Hardcoded in the pipeline** — `MARK_TO_VISUAL` and `_VISUAL_ROLES` in `generator.py`/`transformer.py` are static dicts; adding a new mapping requires a code change.
3. **Discovered by trial and error** — undocumented PBI native visual properties (like `pivotTable.valuesOnRow`) are only found by manually fixing a report in PBI Desktop and inspecting the JSON.
4. **No confidence signal** — the pipeline cannot distinguish "validated in PBI Desktop" from "generated but never checked."

---

## Why PBI Schemas Don't Fully Cover Visual Properties

The MS PBIR schema (`microsoft/json-schemas/fabric/item/report`) defines:
- Container structure (`visualContainer/2.7.0`)
- Generic `objects` shape (`visualConfiguration/2.3.0`)
- Formatting object structure (`formattingObjectDefinitions/1.5.0`)

It does **not** enumerate visual-type-specific properties (`valuesOnRow` for `pivotTable`, axis config for `barChart`, etc.). The `objects` property is a free-form bag even in the latest schema version. Native built-in visual properties are only discoverable from PBI Desktop save output.

The PBI custom visuals API (`learn.microsoft.com/en-us/power-bi/developer/visuals/capabilities`) covers custom visual development only — not built-in native visuals.

**Ground truth for native PBI visual properties = PBI Desktop save output (`visual.json` files).**

---

## Solution: Approach C — Hybrid Registry + Runtime Fallback

Two components: an offline registry builder and a runtime fallback mapper.

```
OFFLINE (run once, or after new validations)
──────────────────────────────────────────────────────────────────────
samples/validation_manifest.yaml        (user declares PBI-validated sheets)
  + output/<stem>.transformed.json       (Tableau source properties per sheet)
  + output/<stem>.Report/.../visual.json (PBI output per sheet)
  + .pbir_schema_cache/ schemas          (structural validation)
  ↓
tab_to_pbi/visual_agent.py
  ↓
samples/visual_mappings.json            (machine-readable tiered registry)
docs/visual_conversion.md               (auto-generated, always accurate)

RUNTIME (each migration run)
──────────────────────────────────────────────────────────────────────
transformer.py
  → reads visual_mappings.json first    (deterministic, no API cost)
  → calls visual_mapper.py for unknowns (Claude, confidence-scored)
      ≥ 0.8 → emit + auto-persist as "inferred", flag for validation
      0.5–0.8 → emit + warning in migration report
      < 0.5 → skip + log as unsupported_low_confidence
  → migration_report.json gains visual_mappings confidence section
```

## Confidence Tiers

| Tier | Condition | Migration behaviour |
|------|-----------|---------------------|
| `validated` | Sheet listed in `validation_manifest.yaml`, PBI Desktop confirmed | Auto-convert, no warning |
| `generated` | Pipeline produced it; not in manifest (structurally valid, visually unverified) | Auto-convert + note in report |
| `inferred` | LLM-mapped with no sample; never generated before | Convert + explicit warning; flag `needs_validation` |

Confidence tiers are **never downgraded** on re-runs. Re-running `visual_agent.py` after adding manifest entries upgrades `generated` → `validated`.

## `samples/visual_mappings.json` Schema

Five top-level sections. Each entry carries `confidence`, `source` (workbook + sheet), `schema_validated` flag, and `schema_ref`.

### 1. `mark_type_mapping`

Tableau mark type → PBI visual type. Replaces `MARK_TO_VISUAL` hardcode.

```json
"mark_type_mapping": {
  "Bar":      { "pbi_visual_type": "barChart",    "confidence": "validated", "source": {...} },
  "Column":   { "pbi_visual_type": "columnChart",  "confidence": "validated", "source": {...} },
  "Line":     { "pbi_visual_type": "lineChart",    "confidence": "validated", "source": {...} },
  "Area":     { "pbi_visual_type": "areaChart",    "confidence": "validated", "source": {...} },
  "Pie":      { "pbi_visual_type": "pieChart",     "confidence": "validated", "source": {...} },
  "Text":     { "pbi_visual_type": "tableEx",      "confidence": "validated", "source": {...} },
  "CrossTab": { "pbi_visual_type": "pivotTable",   "confidence": "validated", "source": {...} },
  "KPI":      { "pbi_visual_type": "cardVisual",   "confidence": "validated", "source": {...} },
  "Circle":   { "pbi_visual_type": "scatterChart", "confidence": "medium",    "source": {...} },
  "Automatic":{ "pbi_visual_type": null, "use_inference_rules": true }
}
```

### 2. `automatic_inference_rules`

Shelf layout conditions → PBI visual type when Tableau mark is `Automatic`.

```json
"automatic_inference_rules": [
  {
    "id": "bar_from_automatic",
    "condition": { "row_shelf": "discrete_dimension", "col_shelf": "continuous_measure" },
    "pbi_visual_type": "barChart",
    "confidence": "validated",
    "source": { "workbook": "...", "sheet": "..." }
  },
  {
    "id": "line_from_automatic_date",
    "condition": { "col_shelf_has_date_part": true, "row_shelf": "continuous_measure" },
    "pbi_visual_type": "lineChart",
    "confidence": "validated",
    "source": { "workbook": "sql_custom_single_date.twb", "sheet": "Sheet 4" }
  },
  {
    "id": "kpi_from_automatic",
    "condition": { "row_shelf": "empty", "col_shelf": "empty", "encodings_text": "measure" },
    "pbi_visual_type": "cardVisual",
    "confidence": "validated",
    "source": { "workbook": "...", "sheet": "Total Sales By Year" }
  }
]
```

### 3. `visual_types`

Per-visual-type: query role mapping + objects (PBI-specific properties).

```json

        "trigger": "show_data_labels == true",

        "confidence": "validated",
        "source": { "workbook": "simple_join_calculated_line_dashboard.twb", "sheet": "Sales Profit" }
      }
    },
    "confidence": "validated",
    "source": { "workbook": "simple_join_calculated_line_dashboard.twb", "sheet": "Sales Profit" }
  },
  "pivotTable": {
    "query_roles": {
      "Columns": { "tableau_shelf": "col",              "field_type": "dimension" },
      "Values":  { "tableau_shelf": "crosstab_measures", "field_type": "measure"  }
    },
    "objects": {
      "valuesOnRow": {
        "trigger": "crosstab_measures_non_empty AND row_fields_empty",
        "pbi_json": { "values": [{"properties": {"valuesOnRow": {"expr": {"Literal": {"Value": "true"}}}}}] },
        "schema_validated": true,
        "schema_ref": "fabric/item/report/definition/visualConfiguration/2.3.0/schema.json",
        "confidence": "validated",
        "source": { "workbook": "simple_join_calculated_line_dashboard_multiple_visual_multiple_dashboard.twb",
                    "sheet": "Sales Profit CrossTab" }
      },
      "subTotals": {
        "trigger": "always",
        "pbi_json": { "subTotals": [{"properties": {
          "rowSubtotals":    {"expr": {"Literal": {"Value": "false"}}},
          "columnSubtotals": {"expr": {"Literal": {"Value": "false"}}}
        }}]},
        "schema_validated": true,
        "schema_ref": "fabric/item/report/definition/visualConfiguration/2.3.0/schema.json",
        "confidence": "validated",
        "source": { "workbook": "simple_join_calculated_line_dashboard_multiple_visual_multiple_dashboard.twb",
```

### 4. `property_mappings`

Cross-cutting properties that apply across multiple visual types.

```json
"property_mappings": {
  "show_data_labels": {
    "pbi_objects_key": "labels",
    "pbi_json": { "labels": [{"properties": {"show": {"expr": {"Literal": {"Value": "true"}}}}}] },
    "applicable_visual_types": ["barChart", "columnChart", "lineChart", "areaChart", "pieChart"],
    "excluded_visual_types": ["tableEx", "pivotTable"],
    "schema_validated": true,
    "schema_ref": "fabric/item/report/definition/visualConfiguration/2.3.0/schema.json",
    "confidence": "validated"
  },
  "visual_title": {
    "pbi_key": "visualContainerObjects.title",
    "applicable_visual_types": ["*"],
    "schema_validated": true,
    "schema_ref": "fabric/item/report/definition/visualContainer/2.7.0/schema.json",
    "confidence": "validated"
  },
  "sort_definition": {
    "pbi_key": "query.sortDefinition",
    "applicable_visual_types": ["*"],
    "confidence": "validated"
  }
}
```

## `visual_agent.py` — Offline Builder Logic

Run: `uv run tab_to_pbi/visual_agent.py`

### Step 1 — Load manifest
Parse `samples/validation_manifest.yaml` → build `validated_lookup[stem][sheet/dashboard]`.

### Step 2 — Scan output pairs
For each workbook stem in `output/`:
- Load `output/<stem>.transformed.json` (Tableau source: mark_type, fields, properties per sheet)
- Walk `output/<stem>.Report/definition/pages/*/visuals/*/visual.json`
- Match sheet name between transformed and visual.json
- Assign confidence tier: `validated` if in manifest, else `generated`

### Step 3 — Extract mappings
From each pair extract:
- `mark_type_mapping` entry
- `automatic_inference_rules` entry (when mark_type is `Automatic`)
- `query_roles` for the visual type
- `objects` entries — diff against empty baseline to capture non-default properties only
- `property_mappings` entries — deduplicate cross-cutting properties

For each `pbi_json` fragment: run `jsonschema.validate()` against the appropriate cached PBIR schema. Set `schema_validated: true` on pass; log warning on fail.

### Step 4 — Fill gaps with Claude
For any visual type in `MARK_TO_VISUAL` with no discovered sample, call Claude with:
- Nearest validated sample (same visual family — e.g. use `barChart` sample for `columnChart`; use `barChart` for `areaChart`; use `tableEx` for `pivotTable` if pivotTable sample absent)
- PBIR `visualConfiguration/2.3.0` schema (structural constraint)
- Tableau XSD summary for the mark type

Store result as `confidence: inferred`.

### Step 5 — Write outputs
- Write `samples/visual_mappings.json` (full registry)
- Regenerate `docs/visual_conversion.md` from registry — each row gets a `[validated]` / `[generated]` / `[inferred]` badge

### Re-run behaviour
- Safe and idempotent
- `validated` entries are never downgraded
- New manifest entries upgrade `generated` → `validated`
- LLM inference only runs for visual types with no sample

## `visual_mapper.py` — Runtime Fallback Logic

### Public API

```python
def load_registry() -> None:
    """Load samples/visual_mappings.json into module-level cache. Call once from main.py."""

def map_visual(sheet: dict, datasource: dict) -> tuple[dict, dict]:
    """
    Resolve visual type, query roles, and objects for a sheet.
    Returns (resolved_visual_info, mapping_result).
    mapping_result carries confidence per resolved property.
    """
```

### Resolution order (for each property)

1. Registry lookup (`validated` or `generated`) — return immediately, no API call
2. Claude fallback — grounded by nearest sample + PBIR schema
   - ≥ 0.8 → emit + auto-persist to registry as `inferred`, flag `needs_validation`
   - 0.5–0.79 → emit + warning in migration report, do NOT persist
   - < 0.5 → skip + log as `unsupported_low_confidence`

### `mapping_result` structure (per sheet, in migration report)

```json
{
  "visual_type":    { "value": "pivotTable", "confidence": "validated", "source": "registry" },
  "query_roles":    { "confidence": "validated", "source": "registry" },
  "objects": {
    "valuesOnRow":  { "confidence": "validated",  "source": "registry" },
    "custom_prop":  { "confidence": "inferred",   "source": "claude",
                      "warning": "unvalidated — add to validation_manifest.yaml after PBI Desktop check" }
  },
  "needs_validation": ["custom_prop"]
}
```

## Pipeline Integration

### `main.py` — startup
```python
from tab_to_pbi.visual_mapper import load_registry
load_registry()
```

### `transformer.py` — `_process_sheets()`
```python
# Before
visual_type = MARK_TO_VISUAL.get(mark_type, "tableEx")

# After
visual_info, mapping_result = visual_mapper.map_visual(sheet, datasource)
visual_type = visual_info["visual_type"]
sheet_output["mapping_result"] = mapping_result
```

`MARK_TO_VISUAL` and `_VISUAL_ROLES` in `generator.py` are kept as **fallback constants** — used only if `samples/visual_mappings.json` is missing (e.g. fresh clone before `visual_agent.py` has been run).

### `migration_report.json` — new section
```json
{
  "translated_fields": [...],
  "unsupported": [...],
  "dashboards": [...],
  "visual_mappings": {
    "Sales Profit":          { "visual_type": "barChart",   "confidence": "validated" },
    "Sales Profit CrossTab": { "visual_type": "pivotTable", "confidence": "validated" },
    "New Unknown Sheet":     { "visual_type": "tableEx",    "confidence": "inferred",
                               "needs_validation": ["custom_objects"] }
  }
}
```

## Schema Validation Scope

| What is validated | Schema used | Catches |
|-------------------|-------------|---------|
| `pbi_json` objects structure | `visualConfiguration/2.3.0` | Wrong `expr/Literal` shape, missing `properties` wrapper |
| `visualContainerObjects` structure | `visualContainer/2.7.0` | Malformed title/subtitle blocks |
| Formatting object values | `formattingObjectDefinitions/1.5.0` | Invalid formatting property types |
| Visual-type-specific property names | *(not in any schema)* | Cannot validate — caught only by PBI Desktop verification |

## What `docs/visual_conversion.md` Becomes

No longer hand-edited. Regenerated by `visual_agent.py` from `visual_mappings.json`. Sections map directly:

| Registry section | Doc section |
|-----------------|-------------|
| `mark_type_mapping` | Visual Type Mapping table |
| `automatic_inference_rules` | Automatic Mark Type Inference table |
| `visual_types[*].query_roles` | queryState Role Mapping sections |
| `property_mappings` | Visual Properties Mapping table |

Each row gets a confidence badge. Rows marked `[inferred]` identify gaps that need PBI Desktop verification before the next migration.

---

## Out of Scope

- Tableau Server API integration
- PBI Service publishing
- Automatic PBI Desktop launch/UI automation
- Custom visual type support (third-party marketplace visuals)
