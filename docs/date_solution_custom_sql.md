# Date Solution — Custom SQL Sources

## Problem

Custom SQL datasources (Tableau `relation type="text"`) with date-part shelf encodings (e.g. `yr:order_date:ok`) failed in PBI with:

```
[Expression.Error] The name 't0.order_date Year' doesn't exist in the current context.
```

And after the hierarchy fix:

```
The 'orders' table contains a Column and a Hierarchy with the same name 'Orderdate'.
```

## Root Causes

**Bug 1 — Missing derived column in NativeQuery result**

The `_build_m_expression` `if custom_sql:` branch returned immediately without processing `date_part_columns` (`dpc`). The TMDL declared `column 'order_date Year'` with `sourceColumn: order_date Year`, but the NativeQuery only returned the original custom SQL columns. When PBI DirectQuery folding generated `SELECT t0."order_date Year" FROM (<query>) t0`, the column didn't exist → error.

**Bug 2 — Case-insensitive hierarchy/column name collision**

The hierarchy name was generated by:
```python
" ".join(w.capitalize() for w in base_col.replace("_", " ").split())
```
For PascalCase columns with no underscores (e.g. SQL Server `OrderDate`), this produces a single word with all-but-first letters lowercased: `Orderdate`. PBI name comparison is case-insensitive within a table, so `OrderDate` (column) and `Orderdate` (hierarchy) collide. Snake_case columns like `order_date` are unaffected because `Order Date` ≠ `order_date` even case-insensitively.

## Solution

### Fix 1 — Subquery wrapping for DirectQuery custom SQL (`generator.py`)

When `custom_sql` is set, `storage_mode == "directQuery"`, and `dpc` is non-empty, wrap the original custom SQL as a subquery and add the dialect-specific EXTRACT expressions on top:

```sql
SELECT t0.*,
  EXTRACT(YEAR FROM t0.order_date)    AS "order_date Year",
  EXTRACT(QUARTER FROM t0.order_date) AS "order_date Quarter",
  EXTRACT(MONTH FROM t0.order_date)   AS "order_date Month",
  EXTRACT(DAY FROM t0.order_date)     AS "order_date Day"
FROM (<original custom SQL>) t0
```

PBI folds `SELECT t0."order_date Year" FROM (<above>) t0` — the column now exists in the subquery result. `EnableFolding=true` is preserved so additional filter push-down works.

For Import mode custom SQL + `dpc`, `Table.AddColumn` steps are chained after the NativeQuery (same as file-based sources).

### Fix 2 — Full date hierarchy injection (`generator.py`)

A new `_expand_to_hierarchy(dpc)` helper expands any detected date-part columns to the full standard set — **YEAR, QUARTER, MONTH, DAY** — per unique base column. This is called in `_write_tmdl_table` only for custom SQL DirectQuery tables, matching the 4 levels PBI Auto date/time creates for Import mode (which is disabled for DirectQuery).

This means a single `yr:order_date` shelf reference produces all four derived columns and a TMDL `hierarchy` block, enabling full drill-down in PBI.

### Fix 3 — Hierarchy name collision guard (`generator.py`)

After computing `hier_name`, check it case-insensitively against all column names in the table. If a collision is found, fall back to `f"{base_col} Hierarchy"`:

```python
col_names_lower = {c["name"].lower() for c in table["columns"]}
if hier_name.lower() in col_names_lower:
    hier_name = f"{base_col} Hierarchy"
```

This applies to all tables (not just custom SQL) and is a no-op for snake_case column names where the generated hierarchy name already differs by underscore vs space.

## Dialect Coverage

All 9 SQL connectors are covered via the existing `_DATE_PART_SQL` table. Column alias quoting in the subquery uses dialect-specific syntax (ANSI `"..."` for postgres/redshift/bigquery/oracle/teradata, backtick for mysql, bracket for sqlserver), built from raw SQL before M-escaping the entire string.

## Scope

| Path | Change |
|------|--------|
| Custom SQL + DirectQuery + `dpc` | Subquery wrap + full hierarchy expansion |
| Custom SQL + Import + `dpc` | `Table.AddColumn` chain after NativeQuery |
| Custom SQL + no `dpc` | Unchanged (original path) |
| Relational tables (non-custom-SQL) | Completely unaffected |

## Files Changed

`tab_to_pbi/generator.py` only — three additions inside `_write_tmdl_table` and `_build_m_expression`:
- `_HIERARCHY_PARTS` constant
- `_expand_to_hierarchy()` helper
- Hierarchy collision guard in the hierarchy loop
- DirectQuery subquery-wrap branch in `if custom_sql:`
- Import AddColumn-chain branch in `if custom_sql:`
